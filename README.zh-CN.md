## 先用起来

通过 [Skills CLI](https://github.com/vercel-labs/skills) 安装：

```sh
npx skills add HUHANG716/discuss --skill discuss
```

然后把方案交给助手。在 Codex 中可以这样说：

```text
用 $discuss 帮我检查这个方案：……
```

也可以直接说“讨论一下这个方案”“discuss 一下这个想法”或“grill 一下这个方案”，相近的讨论表达也适用。

原名 `grill-lite`，现在的技能名称和安装文件夹都是 `discuss`。

## 一次完整的讨论，可以这么短

*以下为示例对话。一次有效回答就可能足够。*

**你**

> 我想把个人任务管理工具重做成一个 Web 应用，用 discuss 帮我看看。

**Discuss**

> 🍢 **第1问：第一版优先解决什么？**
>
> - **A. 不知道先做什么（推荐）**
> - B. 忘记任务
> - C. 看不清进度
>
> 🔥 先让第一版有一个明确的用途。
>
> 回复字母，或直接说你的想法。

**你**

> 其实我想解决的是任务太模糊，不知道怎么开始。只给我自己用，不需要同步。

**Discuss · 收尾**

> 关键选择已经明确，可以先画第一版草图了。
>
> **建议：** 先做一个本地的任务拆解原型，把模糊任务变成可执行的下一步。
>
> **你已确定：** 只给你自己用、不需要同步、重点是拆出下一步行动。
>
> **我采用的假设：** 第一版由你手动补充下一步行动就够了。
>
> **下一步：** 画出任务名称、下一步行动和开始按钮三个元素。
>
> 🍢 **下一步：要先画出这一页的草图吗？**
>
> - **A. 开始画草图（推荐）**
> - B. 调整方案（直接说改哪里）
> - C. 先到这里
>
> 🔥 用一页草图就能检查这条流程是否顺畅。
>
> 回复字母，或直接说你的想法。

你提出了选项之外的方向，助手就跟着你的想法调整。一道讨论题已经足够给出结论，随后单独确认是否开始画草图，等你选择后再执行。

## 值得深入，再多聊一轮

每轮结束都会先总结。有关键疑点或重要改进空间时，Discuss 会给出具体方向，说明深入能解决什么，和“开始执行 / 先停”一起供你选择。

例如，团队看板的原型已经可以画出来，而任务交接值得在扩展前再聊清楚：

> **值得深入：** 任务交接——明确工作转交后由谁负责。
>
> 🍢 **下一步：接下来怎么走？**
>
> - **A. 开始画已确定的原型（推荐）**
> - B. 深入任务交接
> - C. 先到这里
>
> 🔥 先用草图验证已确定的流程，再考虑团队规则。
>
> 回复字母，或直接说你的想法。

选 B 就进入围绕任务交接的新一轮，**仍然最多五题**，已有决定继续保留。题号从**第1问**开始，信息足够就提前结束。每轮之后，都可以按需要再次总结和选择。轮数没有固定上限，每次继续都由你决定。

如果关键疑点妨碍执行，助手会推荐先深入该问题，暂不提供开始执行的选项。如果没有值得深入的方向，工作就绪时仍可选择“开始 / 调整 / 先停”；没有需要选择的下一步时，直接给结论。

## 问得少，仍然问到点上

| 规则 | 带来的体验 |
| --- | --- |
| **一次只问一题** | 你回答后，再决定是否继续问下一题。 |
| **2–3 个选项，标明推荐项** | 选项简短，推荐项排在第一位。 |
| **随时说出自己的想法** | 每题都提示可以自由回答，组合、修改或跳出选项都可以。 |
| **每轮最多 5 题** | 可以更少；先总结，再由你决定是否进入下一轮。 |
| **固定 🍢 / 🔥 格式** | 问题和理由各一句，只显示当前题号。 |
| **小选择采用默认值** | 可逆的细节交给助手，并清楚标明假设。 |
| **信息足够就收尾** | 能给结论就停，剩余题数不用凑满。 |
| **明确选择下一步** | 开始执行、深入具体方向或先停；已经授权执行时直接继续。 |

Discuss 聚焦会改变方向、范围或可行性的选择。推荐会参考已知约束和你已经确认的决定；若推荐改变现有职责或范围，会说明收益和代价。次要、可逆的细节可以采用标明的默认假设，减少追问。每题给出选项，等待你回答。推荐项供你参考，后续讨论跟着你的实际回答调整。

## 节奏由你定

| 你说 | 助手就会 |
| --- | --- |
| `整段讨论总共最多三题。` | 使用跨轮次有效的讨论题总上限。 |
| `继续深入失败后的恢复流程。` | 沿用已有决定，围绕该方向开启新一轮。 |
| `重点看哪些地方可能让方案失败。` | 优先检查影响最大的风险。 |
| `先给结论。` | 立即收尾，给出建议和下一步。 |
| `过一下方案，然后直接实现。` | 讨论结束后，按你的授权继续执行。 |

上限不是配额。信息足够明确的方案可以**零讨论题**。界面只写**第3问**，不会暗示还有两题；这时直接收尾很正常。只有你选择或要求继续，才会开启深入的一轮。

## 放进你正在用的助手

核心就是一份 [SKILL.md](SKILL.md)：纯 Markdown，不需要运行脚本、配置 API 密钥或依赖外部服务。支持 Agent Skills 格式的助手即可使用。Skills CLI 支持 Codex、Claude Code、Cursor 等助手，安装时选择你使用的工具。

技能规则使用英文，讨论会跟随你的语言；中文提问、中文收尾都可以。

```text
用 $discuss 帮我检查这个方案。一次只问一题，每轮最多五题，是否继续深入由我选择。
```

<details>
<summary><strong>手动安装</strong></summary>

将 `SKILL.md` 和可选的 `agents/` 文件夹放到助手技能目录下的 `discuss` 文件夹。分发副本时保留 `LICENSE`。

Codex 的用户级路径之一为 `~/.agents/skills/discuss/`，详见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

</details>

<details>
<summary><strong>提问上限如何计算</strong></summary>

默认每轮最多五道讨论题。每题只涉及一个决策，提供 2–3 个选项和推荐项，等你回答后再继续。开场提问和对方案细节的确认也计数。助手在内部记录上限，只展示当前题号；提前收尾时简短说明原因，再给总结，剩余题数不用凑满。

每轮收尾的一次下一步选择与默认讨论题预算分开计算，不夹带方案问题。选择深入后，新一轮题号重新开始，已有决定持续保留。你明确设置的整段讨论上限仍跨轮次有效；如果限制的是全部提问或交互轮次，收尾选择也计入。用完额度不会自动进入下一轮。

助手会列出 1–2 个值得深入的方向，各用一句话说明价值。优先方向直接出现在下一步选项里；你也可以自由回答，选择另一个方向或提出自己的想法。已授权且可以执行时直接继续；只要建议时仍可选择有价值的深入方向，但不提供执行选项。要求停止或只总结时不再追加选择。无法获得的关键事实会被列为待核实的问题，不靠反复追问假装解决。

这个上限依靠模型遵循指令，并非程序强制计数。[人工行为检查场景](EVALS.md)覆盖循环深入、题号展示、提前停止、自定义上限和执行边界，供评估使用，不代表已通过自动化行为测试。

</details>

## 一起把问题问得更准

欢迎提供一个小例子：哪次追问改变了你的决定，或者哪次已经可以收尾，助手却还在问。[提交 Issue](https://github.com/HUHANG716/discuss/issues)，也欢迎提出具体改进。

好的改进，应该让下一位使用者少一些不必要的来回，更快做出有依据的决定。
